# v0.1 scope

## Goal

Build the smallest trustworthy version of throttle that can govern real LLM spend.

## In scope

### Budgeting

- arbitrary `start` / `end`
- monthly convenience/default
- dollar allocation
- linear pacing
- bank calculation
- time-window borrowing
- rollover on/off
- optional rollover cap
- parent/child budgets

### Accounting

- estimate
- reserve
- execute
- settle/reconcile
- release on failure/cancel
- microdollar integer money
- durable local ledger
- concurrent-safe reservations

### Enforcement

- monitor only
- allow
- wait/queue
- deny

### Bedrock

- Converse
- ConverseStream
- InvokeAgent
- request/response usage capture
- model identity below Bedrock
- agent trace accounting where available

### Visibility

- allocation/spend/remaining
- target spend
- banked/borrowed amount
- current vs sustainable burn
- projected end-of-period spend
- live request activity
- input/output token use
- cost by access provider
- cost by model publisher/family/model
- cost by workload/sub-budget

## Explicitly not v0.1

- automatic model replacement
- cheapest-provider routing
- automatic service-tier changes
- response-conciseness prompt injection
- adaptive output-token caps
- reasoning-effort changes
- quality optimization
- team identity/SSO/RBAC
- enterprise hierarchy/audit/approvals
- chargeback workflows
- hosted SaaS

The architecture should permit these without forcing them into the first implementation.
